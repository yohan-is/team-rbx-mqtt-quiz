# team_RBX MQTT 퀴즈

`assets/team_RBX`에 들어 있는 완성 프로젝트를 사용한다. XIAO의 BOOT 버튼, 내장 LED, Wi-Fi, Mosquitto, 정적 웹 대시보드만으로 구현하며 불필요한 외부 부품이나 프로그램을 추가하지 않는다.

사용자에게 진행 상황, 명령의 의미, 결과, 다음 행동을 가능한 한 한국어로 설명한다. 명령어, 파일명, 라이브러리명, MQTT 토픽처럼 원문을 유지해야 정확한 식별자만 영문으로 쓴다.

## 프로젝트 만들기

1. 이 `SKILL.md`를 기준으로 `assets/team_RBX` 경로를 찾는다.
2. 해당 폴더를 사용자가 요청한 작업 공간으로 복사한다. 별도 이름을 요청하지 않았다면 대상 폴더 이름은 `team_RBX`로 정한다.
3. 대상 폴더가 이미 있으면 내용을 먼저 확인하고 사용자 파일을 보존한다. 기존 파일을 무조건 덮어쓰지 않는다.
4. 도구 설치, 설정 수정, 보드 업로드, 서비스 실행 전에 복사된 `README.md`를 끝까지 읽는다.

## 각 보드 설정하기

1. `firmware/mqtt_classroom/arduino_secrets.h`가 없으면 `arduino_secrets.example.h`를 해당 이름으로 복사한다.
2. 로컬 2.4GHz Wi-Fi 이름과 비밀번호, 현재 브로커 노트북의 IPv4 주소, 보드마다 서로 다른 `DEVICE_NAME`을 입력한다.
3. 완성된 `arduino_secrets.h`의 내용, 특히 Wi-Fi 비밀번호를 출력·커밋·공개하지 않는다.
4. `arduino-cli board list`로 연결 포트를 찾는다. 다른 컴퓨터에서도 COM5일 것이라고 가정하지 않는다.
5. FQBN `esp32:esp32:XIAO_ESP32C6`로 컴파일한 뒤, 발견했거나 사용자가 확인한 포트에만 업로드한다.
6. 업로드 전 시리얼 모니터를 닫고, 업로드가 끝난 뒤에만 115200 baud로 다시 연다.

## 게임 실행하기

1. 모든 보드와 브라우저가 신뢰할 수 있는 같은 Wi-Fi에 연결되어 있는지 확인한다. 호스트 노트북의 Wi-Fi를 임의로 끊거나 다른 네트워크로 변경하지 않는다.
2. 브로커 노트북의 현재 Wi-Fi IPv4를 확인한 다음 `broker/mosquitto.conf`로 Mosquitto를 실행한다.
3. 프로젝트 루트에서 `python -m http.server 8080 -d .\web`으로 정적 웹 서버를 실행한다.
4. 네트워크 변경이나 실제 BOOT 버튼 입력이 필요한 테스트는 사용자에게 맡긴다.
5. 대시보드에 브로커 `ONLINE`이 표시되는지 확인한 뒤, `classroom/<장치이름>/status`에서 각 참가자가 `online`인지 확인한다.
6. 게임 상태 순서를 유지한다. 먼저 `waiting:<시각>`으로 2~5초 무작위 대기하고, `armed` 이후 첫 정상 `buzz`를 승자로 정한 뒤, `finished`에서 모든 LED를 끈다.

## 안전과 작업 범위

- `mosquitto.conf`의 익명 접속은 신뢰할 수 있는 교실 내부망에서만 사용한다. 공유기 포트포워딩으로 1883 또는 9001번 포트를 인터넷에 공개하지 않는다.
- 노트북을 ESP의 AP에 연결하거나 인터넷이 끊길 수 있는 네트워크 변경을 직접 수행하지 않는다.
- 사용자가 통신 규약이나 하드웨어 변경을 명시적으로 요청하지 않았다면 MQTT 토픽과 GPIO 배정을 바꾸지 않는다.
- BOOT 버튼은 GPIO9, active-low 내장 LED는 GPIO15를 사용한다.
- 외부 센서가 연결되지 않았다면 떠다니는 A0 값을 센서 데이터로 사용하지 않는다.

## 검증하기

- 보드 설정이나 펌웨어를 변경했다면 컴파일한다.
- 대시보드를 변경했다면 `web/dashboard.html`의 인라인 JavaScript 구문을 검사하거나 로컬에서 페이지를 연다.
- 전체 MQTT 흐름을 진단할 때 `mosquitto_sub -t 'classroom/#' -v`를 사용한다.
- 작업을 마칠 때 대시보드 주소, 사용한 보드 포트, 실행한 명령, 사용자에게 남은 물리 테스트를 한국어로 정리한다.
